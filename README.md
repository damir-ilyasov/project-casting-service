# project-casting-service

Сервис организации и проведения кастингов: создание проектов и ролей,
регистрация кандидатов, подача и отмена заявок на роли, поиск,
сортировка и статистика.

Консольная версия приложения (ПР1–ПР3) дополнена веб-интерфейсом на
Django (ПР5). Предметная область реализована в виде объектной модели:
данные и связанное с ними поведение объединены в классах `Project`,
`Role`, `Candidate` и `Application` (пакет `models/`, ПР3).

## Возможности

- просмотр проектов и их ролей в браузере;
- просмотр информации об отдельном проекте и статусе его ролей;
- просмотр списка заявок в браузере;
- просмотр информации об отдельной заявке;
- (консольная версия, ПР1–ПР3) поиск и добавление проектов, ролей и
  кандидатов, проверка доступности роли, подача и отмена заявок,
  статистика.

## Используемые технологии

- Python 3;
- Django 5.2 — веб-фреймворк;
- HTML — разметка веб-страниц;
- CSS и Bootstrap 5.3 — оформление страниц;
- pytest — автоматизированные тесты;
- flake8 — проверка качества кода.

## Целевая аудитория

Организаторы кастингов, которым нужно создавать проекты и роли,
регистрировать кандидатов и принимать решения по заявкам.

## Предметная область

Основные сущности предметной области — проект, роль в проекте,
кандидат и заявка. Кандидат подаёт заявку на конкретную роль в
проекте; на роль может быть принята только одна заявка, при этом
отменённая заявка не блокирует роль повторно.

## Основные сущности

### Project — проект

Объект `Project` представляет проект (фильм, сериал, рекламу и т.п.),
для которого проводится кастинг.

Основные атрибуты:
- `id` — уникальный идентификатор проекта;
- `name` — название проекта;
- `roles` — список объектов `Role`, относящихся к проекту.

Основные методы:
- `add_role()` — добавить роль в проект и вернуть созданный объект;
- `find_role()` — найти роль проекта по идентификатору;
- `__str__()` — строковое представление проекта.

### Role — роль

Объект `Role` представляет роль (персонажа или позицию) в проекте.

Основные атрибуты:
- `id` — идентификатор роли в рамках проекта;
- `name` — название роли.

Основные методы:
- `__str__()` — строковое представление роли.

### Candidate — кандидат

Объект `Candidate` представляет кандидата, претендующего на роль.

Основные атрибуты:
- `id` — уникальный идентификатор кандидата;
- `name` — имя кандидата;
- `contact` — контактные данные.

Основные методы:
- `__str__()` — строковое представление кандидата;
- `from_data()` — создание объекта `Candidate` из словаря данных.

### Application — заявка

Объект `Application` представляет заявку кандидата на роль в проекте.
Заявка хранит ссылки на объекты `Candidate`, `Project` и `Role`, а не
только их идентификаторы.

Основные атрибуты:
- `id` — идентификатор заявки;
- `candidate` — объект `Candidate`;
- `project` — объект `Project`;
- `role` — объект `Role`;
- `status` — статус заявки (`pending`, `accepted` или `cancelled`).

Основные методы:
- `accept()` — принять заявку (утвердить кандидата на роль);
- `cancel()` — отменить заявку;
- `is_valid_status()` — статический метод проверки допустимости статуса;
- `__str__()` — строковое представление заявки с учётом статуса.

## Взаимодействие объектов

```
Candidate ──┐
            ├──> Application ──> Project ──> Role
```

Заявка (`Application`) связывает кандидата (`Candidate`) с ролью
(`Role`) конкретного проекта (`Project`). Проверка доступности роли
выполняется по коллекции заявок: роль свободна, если среди заявок на
эту роль нет ни одной со статусом `accepted`. Данные связанных
объектов доступны через атрибуты заявки, например
`application.project.name`, `application.role.name`,
`application.candidate.contact`.

## Страницы веб-интерфейса

- `/` — главная страница: описание приложения и навигация
  (view-функция `index()`);
- `/projects/` — список проектов с их ролями: объекты `Project` из
  `data/projects.json` (view-функция `projects()`);
- `/projects/<int:project_id>/` — страница проекта: карточка со
  списком ролей и статусом каждой роли (view-функция
  `project_detail()`);
- `/applications/` — список заявок: объекты `Application` из
  `data/applications.json` (view-функция `applications()`);
- `/applications/<int:application_id>/` — страница заявки: кандидат,
  проект, роль и статус (view-функция `application_detail()`).

Если проект, роль или заявка с указанным идентификатором не найдены,
страница возвращает код статуса 404 (собственная страница ошибки, а
не техническая страница Django).

## Основные операции

### Используется в веб-интерфейсе (ПР5)

- просмотр списка проектов и их ролей;
- просмотр информации о проекте и доступности каждой роли;
- просмотр списка заявок;
- просмотр информации об отдельной заявке.

### Доступно в консольной версии (ПР1–ПР3)

Эти операции реализованы в ПР2–ПР3 и работают в консольной версии
(`python main.py`). В веб-интерфейсе они появятся, когда будут
добавлены формы и POST-запросы:

- добавление проекта и роли;
- поиск проекта по названию;
- добавление кандидата, поиск кандидата по имени;
- проверка доступности роли;
- подача заявки на роль;
- отмена заявки;
- статистика по проектам и заявкам.

## Хранение данных

Данные приложения хранятся в JSON-файлах:
- `data/projects.json`;
- `data/candidates.json`;
- `data/applications.json`.

При загрузке данные из JSON преобразуются в объекты `Project`, `Role`,
`Candidate` и `Application`. При сохранении объекты преобразуются
обратно в структуры JSON. Для связи заявки с проектом, ролью и
кандидатом в `applications.json` используются их идентификаторы
(`project_id`, `role_id`, `candidate_id`). На ПР5 Django ORM ещё не
используется: JSON остаётся источником данных и для консольной, и для
веб-версии приложения.

## Назначение модулей

### `main.py`

Консольная версия приложения (сохранена с ПР3). Отвечает за: запуск
консольного приложения, отображение меню, получение данных от
пользователя, организацию пользовательских сценариев.

### `casting_site/`

Пакет настроек Django-проекта:
- `settings.py` — настройки проекта (в том числе `INSTALLED_APPS`,
  `LANGUAGE_CODE = "ru-RU"`, `TIME_ZONE = "Europe/Moscow"`);
- `urls.py` — маршрутизация верхнего уровня, подключает маршруты трёх
  приложений через `include()`, объявляет `handler404`;
- `asgi.py`, `wsgi.py` — точки взаимодействия с сервером.

### `homepage/`

Django-приложение, отвечающее за главную страницу:
- `views.py` — функция `page()` (общий HTML-каркас: кодировка,
  заголовок, Bootstrap, навигация), view-функция `index()` и
  обработчик ошибки 404 `page_not_found()`;
- `urls.py` — маршрут главной страницы.

Функция `page()` размещена здесь, потому что главная страница задаёт
общий вид всех остальных страниц — она точка входа в проект. Остальные
приложения импортируют её.

### `projects/`

Django-приложение, отвечающее за проекты и роли:
- `views.py` — view-функции `projects()` (список) и `project_detail()`
  (карточка проекта со статусом ролей), использует функции пакета
  `models/` и `storage.py`;
- `urls.py` — маршруты приложения;
- `models.py` — Django-модели (заполняется в следующих работах).

### `applications/`

Django-приложение, отвечающее за заявки:
- `views.py` — view-функции `applications()` (список) и
  `application_detail()` (карточка заявки);
- `urls.py` — маршруты приложения;
- `models.py` — Django-модели (заполняется в следующих работах).

### `models/`

Классы предметной области и функции работы с ними (пакет ПР3):
- `projects.py` — классы `Project`, `Role` и функции работы с
  коллекцией проектов: `add_project()`, `find_project()`,
  `find_project_by_id()`, `filter_projects_with_open_roles()`,
  `sort_projects_by_role_count()`;
- `candidates.py` — класс `Candidate` и функции работы с коллекцией
  кандидатов: `add_candidate()`, `find_candidate()`,
  `find_candidate_by_id()`;
- `applications.py` — класс `Application` и функции работы с
  коллекцией заявок: `is_role_available()`, `create_application()`,
  `cancel_application()`, `find_application_by_id()` (используется
  веб-страницей заявки, добавлена в ПР5), `get_application_status()`,
  `get_applications_statistics()`.

### `storage.py`

Отвечает за загрузку и сохранение данных. Выполняет преобразование:
JSON → объекты Python; объекты Python → JSON. Используется и
консольной версией, и веб-представлениями (`projects/views.py`,
`applications/views.py`).

### `utils.py`

Содержит вспомогательные функции консольного ввода: `input_int()`,
`input_nonempty_str()` — безопасный ввод данных с повтором запроса при
ошибке.

### `tests/`

Содержит автоматизированные тесты проекта (16 тестов): создание и
работу объектов `Project`, `Role`, `Candidate`, `Application`, методы
классов, операции с коллекциями, создание и отмену заявок, поиск по
идентификатору, правило доступности роли.

## Запуск приложения

Веб-версия (Django):

```
python manage.py migrate
python manage.py runserver
```

```
http://127.0.0.1:8000/
```

```
python main.py
```
