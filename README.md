# project-casting-service

Сервис организации и проведения кастингов: создание проектов и ролей,
регистрация кандидатов, подача и отмена заявок на роли, поиск,
сортировка и статистика.

## 1. Назначение проекта

Casting Service — учебное приложение для управления кастинговыми
проектами. Проект позволяет хранить сведения о проектах, ролях,
кандидатах и заявках, выполнять основные операции с этими объектами
и предоставлять доступ к информации через веб-интерфейс Django.

Проект развивается поэтапно: консольная версия (ПР1–ПР3) дополнена
веб-интерфейсом на Django (ПР5), который в ПР6 переведён с
формирования HTML-кода в Python на систему шаблонов Django.

## 2. Используемые технологии

- Python 3;
- Django 5.2;
- Django Template Language (DTL);
- HTML5;
- CSS3;
- JavaScript;
- Bootstrap 5;
- JSON как исходный формат данных;
- SQLite через стандартный модуль `sqlite3` (ПР7);
- Git;
- pytest;
- flake8.

## 3. Предметная область

В системе используются четыре основные сущности:
- Проект (`Project`) — идентификатор, название и список ролей;
- Роль (`Role`) — идентификатор и название в рамках проекта;
- Кандидат (`Candidate`) — идентификатор, имя и контакт;
- Заявка (`Application`) — идентификатор, ссылки на кандидата, проект
  и роль, статус (`pending`, `accepted` или `cancelled`).

Для предметной области реализованы собственные Python-классы (пакет
`models/`, ПР3). JSON-файлы сохранены как исходный источник данных.
В ПР7 добавлена отдельная база SQLite, к которой приложение обращается
через стандартный модуль `sqlite3`; Django ORM по-прежнему не используется.

## 5. Веб-интерфейс

Веб-часть приложения реализована на Django. Основные страницы:
- главная страница (`/`);
- список проектов (`/projects/`);
- информация об отдельном проекте (`/projects/<id>/`);
- список заявок (`/applications/`);
- информация об отдельной заявке (`/applications/<id>/`).

Для формирования страниц используются Django-шаблоны. Генерация HTML
непосредственно в Python-коде веб-представлений не используется.
Представления подготавливают данные и передают их в шаблоны через
контекст.

## 6. Django Template Language

### Базовый шаблон

Общий шаблон страницы: `templates/base.html`. Он содержит общую
HTML-структуру страницы, подключение стилей и JavaScript, логотип и
блоки для содержимого отдельных страниц.

Дочерние шаблоны используют наследование:
```
{% extends "base.html" %}
```
Содержимое отдельной страницы размещается в блоке:
```
{% block content %}
{% endblock %}
```
Заголовок страницы задаётся через блок:
```
{% block title %}
{% endblock %}
```

### Включаемые шаблоны

Повторяющиеся фрагменты вынесены в отдельные шаблоны:
- навигация — `templates/includes/navigation.html`;
- карточка проекта — `projects/templates/projects/includes/project_card.html`;
- статус заявки — `applications/templates/applications/includes/application_status.html`.

Подключение выполняется через:
```
{% include "includes/navigation.html" %}
{% include "projects/includes/project_card.html" %}
{% include "applications/includes/application_status.html" %}
```

### Контекст

Представления передают данные в шаблоны через словарь контекста.
Например, для списка проектов:
```python
context = {
    "projects": projects_list,
}
```
В шаблоне данные доступны по имени переменной:
```
{% for project in projects %}
```

### Циклы и условия

Для формирования списков используются циклы:
```
{% for project in projects %}
{% empty %}
    <p>Проектов пока нет.</p>
{% endfor %}
```
Условия используются для отображения различного содержимого страницы
и состояния заявки, например:
```
{% if item.available %}
    <span class="badge bg-success">свободна</span>
{% else %}
    <span class="badge bg-danger">занята</span>
{% endif %}
```
а также для статуса заявки (`pending` / `accepted` / `cancelled`) и
для обработки отсутствующего проекта или заявки (`{% if project %}`).

## 7. Фильтры шаблонов

В шаблонах используются стандартные фильтры Django Template Language:
- количество элементов: `{{ projects|length }}`, `{{ applications|length }}`,
  `{{ project.roles|length }}`;
- значение по умолчанию: `{{ project.name|default:"Без названия" }}`.

Фильтры используются для представления данных и не содержат
бизнес-логику приложения.

## 8. URL-маршрутизация

Для страниц используются именованные маршруты Django. Примеры:
```
{% url 'projects:list' %}
{% url 'projects:detail' project.id %}
{% url 'applications:list' %}
{% url 'applications:detail' application.id %}
{% url 'homepage:index' %}
```
Для приложений используются пространства имён (`app_name`), что
позволяет обращаться к маршрутам через имена вида `projects:list`,
`projects:detail`, `applications:list`, `applications:detail`,
`homepage:index`. Ссылки в шаблонах формируются через `{% url %}`,
а не за счёт жёстко заданных адресов.

## 9. Статические файлы

Статические файлы проекта находятся в каталоге:
```
homepage/static/homepage/
```
Используются:
- `css/style.css`;
- `js/main.js`;
- `img/logo.png`.

Для работы со статическими файлами в шаблонах используется:
```
{% load static %}
```
CSS подключается через:
```
{% static 'homepage/css/style.css' %}
```
Изображение:
```
{% static 'homepage/img/logo.png' %}
```
JavaScript:
```
{% static 'homepage/js/main.js' %}
```
В проекте используется собственный CSS для оформления элементов
интерфейса (карточка проекта, статус заявки, логотип). JavaScript
используется для небольшого динамического поведения интерфейса —
автоматического отображения текущего года в подвале страницы.

## 10. Хранение данных

На текущем этапе данные приложения хранятся в JSON-файлах:
- `data/projects.json`;
- `data/candidates.json`;
- `data/applications.json`.

Загрузка данных выполняется средствами модуля `storage.py`.
Предметные объекты создаются на основе собственных Python-классов из
каталога `models/`. Django ORM на текущем этапе не используется.
Каталоги и файлы, связанные с будущей работой с моделями Django
(`projects/models.py`, `applications/models.py`, `homepage/models.py`,
`migrations/`), сохраняются для дальнейшего развития проекта.

## 11. Основные модули

- `storage.py` — загрузка данных из JSON-файлов для консольной версии;
- `db/database.py` — соединение SQLite и создание схемы;
- `db/import_json.py` — импорт данных из JSON в SQLite;
- `db/queries.py` — SQL-запросы, используемые веб-представлениями;
- `sql/schema.sql` — схема таблиц и индексы;
- `sql/queries.sql` — примеры SQL-запросов (WHERE, JOIN, GROUP BY, HAVING,
  агрегатные функции, сортировка и LIMIT);
- `models/` — классы предметной области: `Project`, `Role`,
  `Candidate`, `Application`;
- `main.py` — консольный вариант работы с приложением;
- `utils.py` — вспомогательные функции для консольного интерфейса;
- `projects/views.py` — обрабатывает веб-запросы, связанные с
  проектами и ролями;
- `applications/views.py` — обрабатывает веб-запросы, связанные с
  заявками;
- `homepage/views.py` — содержит представление главной страницы и
  обработчик ошибки 404.

## 12. Тестирование

В каталоге `tests/` находятся тесты основных классов предметной
области:
```
tests/
├── test_applications.py
├── test_candidates.py
└── test_projects.py
```
Тесты проверяют работу основных операций с проектами, ролями,
кандидатами и заявками. Для запуска тестов используется:
```
pytest -v
```

## 13. Проверка качества кода

Для проверки соответствия кода требованиям PEP 8 используется
flake8. Запуск проверки:
```
flake8 . --extend-exclude=venv
```

## 14. Запуск проекта

Для запуска Django-сервера необходимо перейти в каталог проекта и
выполнить:
```
python manage.py runserver
```
После запуска веб-интерфейс доступен по адресу:
```
http://127.0.0.1:8000/
```
Консольная версия приложения запускается отдельно:
```
python main.py
```

## 16. Текущее состояние проекта

На текущем этапе Casting Service содержит:
- предметные классы `Project`, `Role`, `Candidate`, `Application`;
- консольный интерфейс;
- исходные данные в JSON и импорт в SQLite;\n- SQL-схему с таблицами, связями и индексами;\n- SQL-запросы с фильтрацией, JOIN и агрегатами;
- Django-проект с тремя приложениями (`homepage`, `projects`,
  `applications`);
- веб-представления для основных сущностей;
- Django Template Language;
- наследование шаблонов (базовый шаблон `base.html`);
- блоки шаблонов (`block title`, `block content`);
- включаемые шаблоны (`include`);
- циклы и условия в шаблонах;
- фильтры шаблонов (`length`, `default`);
- именованные URL и пространства имён (`app_name`);
- статические CSS, JavaScript и графический файл;
- собственное оформление интерфейса;
- тесты предметной области.

Формы Django, модели Django ORM и работа с базой данных в текущей
версии проекта не реализованы.

## 17. Дальнейшее развитие

Следующие этапы развития проекта предполагают переход от хранения
данных в JSON к использованию базы данных и Django ORM, а также
реализацию форм Django и дальнейшее расширение веб-интерфейса. В
дальнейшем веб-приложение может быть дополнено операциями создания,
изменения и удаления объектов, обработкой пользовательского ввода,
валидацией данных и API.
