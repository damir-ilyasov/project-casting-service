# project-casting-service

Консольное приложение для организации и проведения кастингов: создание
проектов и ролей, регистрация кандидатов, подача и отмена заявок на
роли, поиск, сортировка и статистика.

С ПР3 предметная область реализована в виде объектной модели: данные и
связанное с ними поведение объединены в классах `Project`, `Role`,
`Candidate` и `Application` вместо словарей и отдельных функций ПР2.

## Возможности

- просмотр и поиск проектов по названию;
- добавление проектов и ролей;
- просмотр и поиск кандидатов по имени;
- добавление кандидатов;
- проверка доступности роли (занята ли она уже принятой заявкой);
- подача заявки кандидата на роль;
- отмена заявки;
- просмотр списка заявок;
- статистика: количество проектов, ролей, заявок по статусам,
  сортировка проектов по числу ролей.

## Целевая аудитория

Организаторы кастингов, которым нужно создавать проекты и роли,
регистрировать кандидатов и принимать решения по заявкам.

## Предметная область

Основные сущности предметной области — проект, роль в проекте,
кандидат и заявка. Кандидат подаёт заявку на конкретную роль в
проекте; на роль может быть принята только одна заявка, при этом
отменённая заявка не блокирует роль повторно.

## Основные сущности

### Project — проект

Объект `Project` представляет проект (фильм, сериал, рекламу и т.п.),
для которого проводится кастинг.

Основные атрибуты:
- `id` — уникальный идентификатор проекта;
- `name` — название проекта;
- `roles` — список объектов `Role`, относящихся к проекту.

Основные методы:
- `add_role()` — добавить роль в проект и вернуть созданный объект;
- `find_role()` — найти роль проекта по идентификатору;
- `__str__()` — строковое представление проекта.

### Role — роль

Объект `Role` представляет роль (персонажа или позицию) в проекте.

Основные атрибуты:
- `id` — идентификатор роли в рамках проекта;
- `name` — название роли.

Основные методы:
- `__str__()` — строковое представление роли.

### Candidate — кандидат

Объект `Candidate` представляет кандидата, претендующего на роль.

Основные атрибуты:
- `id` — уникальный идентификатор кандидата;
- `name` — имя кандидата;
- `contact` — контактные данные.

Основные методы:
- `__str__()` — строковое представление кандидата;
- `from_data()` — создание объекта `Candidate` из словаря данных.

### Application — заявка

Объект `Application` представляет заявку кандидата на роль в проекте.
Заявка хранит ссылки на объекты `Candidate`, `Project` и `Role`, а не
только их идентификаторы.

Основные атрибуты:
- `id` — идентификатор заявки;
- `candidate` — объект `Candidate`;
- `project` — объект `Project`;
- `role` — объект `Role`;
- `status` — статус заявки (`pending`, `accepted` или `cancelled`).

Основные методы:
- `accept()` — принять заявку (утвердить кандидата на роль);
- `cancel()` — отменить заявку;
- `is_valid_status()` — статический метод проверки допустимости статуса;
- `__str__()` — строковое представление заявки с учётом статуса.

## Взаимодействие объектов

```
Candidate ──┐
            ├──> Application ──> Project ──> Role
```

Заявка (`Application`) связывает кандидата (`Candidate`) с ролью
(`Role`) конкретного проекта (`Project`). Проверка доступности роли
выполняется по коллекции заявок: роль свободна, если среди заявок на
эту роль нет ни одной со статусом `accepted`. Данные связанных
объектов доступны через атрибуты заявки, например
`application.project.name`, `application.role.name`,
`application.candidate.contact`.

## Основные операции

### Работа с проектами

- добавление проекта;
- поиск проекта по названию;
- добавление роли в проект;
- фильтрация проектов с ролями;
- сортировка проектов по числу ролей;
- просмотр списка проектов.

### Работа с кандидатами

- создание кандидата;
- поиск кандидата по имени;
- просмотр информации о кандидатах.

### Работа с заявками

- создание заявки;
- проверка доступности роли;
- отмена заявки;
- просмотр списка заявок;
- статистика по заявкам.

При создании заявки проверяется отсутствие уже принятой заявки на ту
же роль того же проекта.

## Хранение данных

Данные приложения хранятся в JSON-файлах:
- `data/projects.json`;
- `data/candidates.json`;
- `data/applications.json`.

При загрузке данные из JSON преобразуются в объекты `Project`, `Role`,
`Candidate` и `Application`. При сохранении объекты преобразуются
обратно в структуры JSON. Для связи заявки с проектом, ролью и
кандидатом в `applications.json` используются их идентификаторы
(`project_id`, `role_id`, `candidate_id`).

## Назначение модулей

### `main.py`

Точка входа в приложение. Отвечает за: запуск приложения, отображение
меню, получение данных от пользователя, организацию пользовательских
сценариев (просмотр, поиск, создание объектов, подача и отмена заявок).

### `models/projects.py`

Содержит классы `Project`, `Role` и функции работы с коллекцией
проектов: `add_project()`, `find_project()`, `find_project_by_id()`,
`filter_projects_with_open_roles()`, `sort_projects_by_role_count()`.

### `models/candidates.py`

Содержит класс `Candidate` и функции работы с коллекцией кандидатов:
`add_candidate()`, `find_candidate()`, `find_candidate_by_id()`.

### `models/applications.py`

Содержит класс `Application` и функции работы с коллекцией заявок:
`is_role_available()`, `create_application()`, `cancel_application()`,
`get_application_status()`, `get_applications_statistics()`.

### `storage.py`

Отвечает за загрузку и сохранение данных. Выполняет преобразование:
JSON → объекты Python; объекты Python → JSON.

### `utils.py`

Содержит вспомогательные функции общего назначения: `input_int()`,
`input_nonempty_str()` — безопасный ввод данных с повтором запроса при
ошибке.

### `tests/`

Содержит автоматизированные тесты проекта, адаптированные к объектной
модели.

## Запуск приложения

```
python main.py
```

После запуска отображается главное меню.

## Запуск тестов

```
pytest -v
```

Тесты проверяют:
- создание и работу объектов `Project`, `Role`, `Candidate`,
  `Application`;
- методы классов (`add_role`, `find_role`, `accept`, `cancel`);
- операции с проектами и кандидатами (поиск, фильтрация, сортировка);
- создание и отмену заявок, связь заявки с проектом, ролью и
  кандидатом;
- правило доступности роли.
